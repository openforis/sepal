# Earth Engine verification scripts

Runnable checks against live Earth Engine. They build real Earth Engine graphs, so they need Earth Engine
credentials and are **not** part of `npm test`.

## Why these are not Jest tests

Jest cannot construct `ee.Projection` in this module's environment, so anything building a real Earth Engine
graph cannot run under it. These scripts are evidence, not CI protection: nothing runs them automatically.

## The scripts

| Script | Checks |
| --- | --- |
| `samplingDesignGridInvariants.mjs` | Graph shape - two `reduceToVectors`, one `reproject`, and that the reproject's input subtree reaches the categorical source and never the lattice branch. That the Arrangement CRS moves the lattice. That changing the Stratification pixel size changes membership but never translates the lattice. That both raster arrangements exclude a boundary-coincident point. |
| `randomGridExactness.mjs` | Stratified Random candidates against an independently enumerated exact-point oracle, across same-CRS, cross-CRS, shifted, 1:1 and 2:1 grid fixtures, plus batch export, asset validation and cleanup. |
| `systematicLatticeExactness.mjs` | Stratified Systematic lattice candidates against the same style of oracle, including exact source-pixel corners, isolated one-pixel classes and repair density. |
| `assetPropertyLimits.mjs` | What Earth Engine persists as asset metadata, per write path: value size, property count and aggregate size against an Image asset, an ImageCollection asset, an image export, and a one-feature table export. Runs the raw API and SEPAL's own `replaceAssetProperties$` over the same payloads, so application filtering and server limits can be told apart. Every case is read back through a fresh request and compared key by key. `cleanup` deletes only assets this run created (`EE_PROPS_RUN`), pages through the listing, and reports what it could not establish rather than reporting nothing left. A task that has to be cancelled is reported cancelled only once a terminal state is confirmed; otherwise it is reported unresolved and its destination is left in place. Nothing is deleted - by `cleanup`, or by a case clearing its own destination for a rerun - while Earth Engine reports a task of this run outside a terminal state, or while the task states cannot be established. |
| `bandEncodingPersistence.mjs` | Whether a band encoding larger than one asset property survives a live export and a live collection write, and reads back as the same facts. Uses production's own representation, property writer and reader: `image` exports one tiny image, `collection` writes a collection's properties through `replaceAssetProperties$` and exports one tile, `read` reports what any asset states as this release reads it, and `cleanup` removes only this run's assets, under the same task-state guard, and reports outstanding tasks. |
| `ccdcOutputBandSelection.mjs` | That a live Masking over CCDC, asked for the physical bands of a measure it does not break on, returns exactly those bands in the order named and keeps the mask. Both sample points lie INSIDE the AOI and the unmasked segments are checked valid at both, so clipping cannot be what separates them and only the added mask can. The recipes are held in memory and read through a RecipeScope of the run's own, so nothing is saved and no asset is written; segmentation is evaluated at two points. Read-only, so it does not establish that Earth Engine would accept an export of those bands. |
| `declaredOutputBands.mjs` | Whether what a recipe says it provides is what it builds: `getBands$()` against the band names of the image `getImage$()` returns. Each fixture is asked three times, because they are different questions - asked for exactly the bands it declares, a producer must return those and no others; asked for a subset of them in an order it does not build in, it must return that subset in that order; and asked for its own arguments it builds whatever it builds, with anything beyond the declared list reported rather than judged. Covers CCDC's count map product - asked for as a map layer asks, by selection rather than as an export - the Change Alerts change product over an in-memory CCDC reference, and BAYTS Alerts over an in-memory BAYTS Historical reference, as both the alert product and a radar map mode. Read-only: recipes are held in memory and read through a RecipeScope of the run's own. Another recipe family is one more `FIXTURES` entry. |
| `assetCollectionSchema.mjs` | What an Asset recipe over a collection says it holds, against what execution builds: for every composite, over Dynamic World and an array-bearing collection (Global CCDC), the one-contributing-image schema must equal the full composite's band names and array dimensionality, and for median, mean, mode and standard deviation over array bands both reads must fail with Earth Engine's refusal; any other failure fails the run. Also a heterogeneous collection (Sentinel-1) filtered away from its first image's bands, `ASSET_BOUNDS` recipes described without their collection's geometry, an empty date window failing with its reason, and a raw collection read from its first image. Reports each read's elapsed time. Read-only. |
| `classificationOutputBands.mjs` | Whether Classification and Remapping build what their shared declarations say: names, order and scalar shape of the running image for Random Forest, SVM, Naive Bayes and Minimum Distance classifiers, a legend not stored in value order, and a Remapping with and without legend entries. An export's arguments must build and return a mixed selection in the order requested. Without legend entries, a probability-capable Classification's default output must be refused by Earth Engine while its class alone still builds. One Landsat scene and nine inline training points. Read-only. |
| `classChangeConfidence.mjs` | Class Change's two bands, by value and mask at one pixel, for every way its images can carry probability bands - complete, partial, differing, missing on either or both - at a zero and a nonzero minimum confidence. Confidence is measured where both images carry probabilities and masked where either carries none; the transition is computed either way and keeps an input mask. Also checks the pixel code of every transition between legends ordered neither numerically nor as text against the code the GUI labels it with. Runs the real calculation over synthetic constant images, with only `imageFactory` substituted, so it needs `--experimental-test-module-mocks`. Read-only. |
| `landTrendrOutputBands.mjs` | Whether LandTrendr's change result is what its shared declaration says: names, order and scalar shape of the running image when asked for nothing, for its changes by mode alone as a map layer asks, for every declared band as an export asks, and for a subset out of order, which must come back in the order asked. A small area and a short series. Unexpected errors fail the run. Checks schema, not pixels. Read-only. |
| `landTrendrAnnualMosaicBands.mjs` | Whether LandTrendr's annual mosaic is what its declared map product says: the image built when every declared band is asked for holds exactly those, in order and scalar, for a fitted year, for no year and for a year after the fitted range. Asked for nothing it lacks exactly the declared indexes and holds exactly `qa` and the four date bands besides, and no year builds the same image as the last fitted year. Unexpected errors fail the run. Checks schema, not pixels or whether imagery exists. Read-only. |
| `baytsAlertsOutputBands.mjs` | Whether BAYTS Alerts' alerts are what its shared declaration says: names, order and scalar shape of the running image for a run initialized from its own alerts and one continued from a previous run's, when asked for nothing, as a filtered map layer asks, for every declared band as an export asks, and for a subset out of order, which must come back in the order asked. The historical reference and previous alerts are held in memory rather than saved. A small area and short periods. Unexpected errors fail the run. Checks schema, not pixels. Read-only. |
| `changeAlertsOutputBands.mjs` | Whether Change Alerts' changes are what its shared declaration says: its catalogue answers the declared names, with and without a monitoring period, and the running image holds exactly the declared bands, in order and scalar, over an optical CCDC reference, a Masking over it and a radar CCDC reference, when asked for nothing, as a map layer asks and for every declared band as an export asks. A subset out of order comes back in the order asked, and every confirmation option off changes no band. A period without observations passes only when Earth Engine refuses it as an empty collection, and a recipe stating no period only when it is refused for that; any other error fails the run. References are held in memory. Planet sources and segments assets are not covered. Checks schema, not pixels. Read-only. |
| `radarMosaicOutputBands.mjs` | Whether Radar Mosaic is what its shared declaration says, for a point in time and a time scan under minimal and saved-default options: its catalogue answers the configuration's declared bands whatever is selected, and the running image holds exactly those, in order and scalar, when asked for nothing, for an empty selection and for every declared band. Subsets out of order, including harmonic-only and harmonic-free time-scan subsets, come back in the order asked. A target date beside a period builds a point in time, and a recipe stating no dates passes only when Earth Engine refuses it for its missing dates. A point in time asked for nothing computes no harmonics, so its six bands are compared pixel by pixel, values and masks, with those of an image computing them, over a small window at the native scale; a time scan's harmonics must hold valid pixels. Explicit requests for undeclared construction bands, and BAYTS Historical's selection, still build. Any other error fails the run. Read-only. |
| `bandMathOutputBands.mjs` | Whether Band Math is what its shared declaration says: its catalogue answers the configured output names in configured order whatever is selected, and its running image holds exactly those bands when asked for nothing and for an empty selection, while a subset out of order comes back in the order asked. Described through the shared resolver from an observation of that image, it is ready with every verified scalar averaged. Over an in-memory CCDC, an expression over its coefficients cast to `float` and its segment starts passed through are observed as arrays of two and one dimensions, each sampled. The Earth Engine operations Band Math applies, checked on their own, decide dimensionality: a cast keeps an array an array, an expression over an array yields one, a mean over arrays is refused, a maximum keeps them and a count is scalar. Two output bands named alike are refused before anything is observed, while Earth Engine builds them with the second renamed; no output bands describes none, while Earth Engine refuses to build it. One pixel value is compared: a doubled elevation cast to `int16`. Read-only, over public assets and an in-memory CCDC read through a RecipeScope of the run's own; over CCDC only band types are evaluated. |
| `stackOutputBands.mjs` | Whether Stack is what its shared declaration says: its catalogue answers the output names its mapping gives, in model order, whatever is selected, and its running image holds exactly those bands when asked for nothing and for an empty selection, while a selection comes back in model order. Described through the shared resolver from its assets' own band evidence, each output band takes its input band's dimensionality and a verified scalar with no stated policy is averaged. One asset stacked twice is described and built under distinct names. CCDC's coefficients and segment starts, stacked under new names beside an asset, are built and described with the same names and dimensions, sampled, beside an averaged scalar. A repeated output name and an input with no mapping are refused before anything is read, and a band the input does not hold once it is read, each beside what Earth Engine does with it: builds the second name renamed, refuses the missing band, and names the unmapped input. One pixel value is compared: a renamed elevation against its source. Read-only, over public assets and an in-memory CCDC read through a RecipeScope of the run's own; over CCDC only band types are evaluated. |
| `phenologyPyeoOutputBands.mjs` | Whether Phenology and PyEO Alerts build what their shared declarations say. Phenology, over an area with months without scenes and one with scenes every month: unselected and empty selections return every declared band in order, all scalar; a subset returns in the order asked; a month without scenes is its band with no valid pixels; a month with scenes keeps its plain median's values, mask, pixel type, CRS and affine transform. PyEO's change report, from the real algorithm over small synthetic inputs with the index-drop gate on and off, holds exactly the declared bands. A comparison without a sample, or an unexpected error, fails the run. Checks schema, not pixel correctness. Read-only. |
| `proportionsAreaWeighting.mjs` | The anticipated-proportions `reduceRegion` on real Earth Engine: that every group carries `stratum`, `weighted` and `area`, that both sums match a masked single-sum oracle, that the proportions match integrals of `cos(latitude)` derived independently, and that they are nowhere near the unweighted mean. Runs the production reducer, not a copy. |

## Running

From the bind-mounted `gee` module container:

```
docker exec -w /usr/local/src/sepal/modules/gee gee node verify/samplingDesignGridInvariants.mjs
```

Read-only checks authenticate with the service account. Modes that write an asset read linked-user credentials
from stdin and are selected with an `SD_*`, `EE_PROPS_*` or `EE_ENC_*` environment variable; each script's
`main()` lists its own modes. Credentials arrive on stdin as one line of JSON - never as an argument or an
environment variable.

`bandEncodingPersistence.mjs` is controlled by:

| Variable | Default | Effect |
| --- | --- | --- |
| `EE_ENC_MODE` | `plan` | `plan`, `image`, `collection`, `rewrite`, `read` or `cleanup` |
| `EE_ENC_ASSET` | - | the asset `read` reports on; required by that mode |
| `EE_ENC_RUN` | `run1` | names this run's assets and tasks, and is what cleanup deletes by |
| `EE_ENC_NAMESPACE` | `sepal_band_encoding_persistence` | the scratch folder under the project's assets |
| `EE_ENC_MEASURES` | `24` | Slice measures behind the payload, which sets how many bands are encoded |
| `EE_ENC_SERVICE_ACCOUNT` | - | `1` authenticates with the service account instead of reading stdin |
| `EE_ENC_TASK_TIMEOUT_MS` | `900000` | how long a task may run before cancellation is requested |
| `EE_ENC_CANCEL_CONFIRM_MS` | `120000` | how long a terminal state is awaited after that request |

Set Earth Engine automatic retries to zero, start one batch task at a time, and confirm a terminal state plus
asset cleanup or intentional retention before starting another.

Authentication establishes the client and nothing else. Only a mode that writes fixtures provisions a scratch
folder, so reading, inspecting and cleaning up need no permission to create one.

`probeRun.mjs` and `eeFailures.mjs` hold what the two metadata probes share: how a mode is selected and what it
may create, what an Earth Engine refusal means, and when a run may delete what it created. Cleanup and reruns
are fresh processes, so the operation listing - every page of it - is the only thing that can say whether a
task of this run is still writing to a destination. Those two are covered by `test/verify/`; the scripts
themselves stay hand-run.

Earth Engine answers a lookup for an asset that is missing and one the caller may not see with the same words,
so a probe carries that answer as `NOT_VISIBLE` and never as absence. A creation attempt may follow it, because
creating cannot overwrite an existing asset; a deletion that ends there is reported as a failure, and the count
of what remains is of what the listing showed, not of what was removed.
